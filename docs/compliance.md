## 6. 腾讯云接入商核查（R11 → D35 闭环）

**背景**：域名在腾讯云备案（接入商 = 腾讯云），实际解析到 Cloudflare 境外 IP，不满足「实际解析 IP 归属须与接入服务商一致」的核查项。

**腾讯云智能客服答复原文（2026-09-28，截图留档）**：

> 「可以，但不能理解为随便加一条无业务关联的子域名就一定能通过。当前规则是：**已备案服务的主域名或实际使用的子域名，至少有一条解析指向腾讯云中国大陆资源；核查不是只看根域名，也不是把全部 DNS 记录逐条判定。**」
>
> 「**如果主域名及实际网站仍全部通过境外 CDN 提供服务，仅新增一个不承载业务的境内子域名，无法保证核查通过，仍可能按实际服务解析判定。**建议将实际提供备案服务的域名或子域名解析至腾讯云境内资源，并办理对应接入备案；若业务全程使用境外资源，可考虑取消腾讯云接入。」

**判定（D35，2026-09-28 定案）**：

1. **占位子域式 A 方案被官方口径否决**（不承载业务的子域无法保证过核查）。能可靠过核查的是 A′（子域承载真实业务 = 部分内容真迁境内），属架构迁移，按「成本远高于风险」否决。
2. **处置 = B：接受风险 + 端上离线快照兜底**（快照与 prefs 不参与 LRU 淘汰，见 api-contract.md §7）。两件前置已完成：控制台无核查待办、预留手机/邮箱可达。
3. ⚠️ **客服末句「可考虑取消腾讯云接入」不可照做**：取消接入 → 无接入信息 → 空壳网站 → 管局注销备案 → `request` 合法域名失效 → 小程序不可用。
4. **升级路径（仅真收到整改通知时启用）**：把 `/api/v1/**` 的 JSON 迁腾讯云 COS 境内 region（灰云子域承载真实业务 + 办理接入变更），或整站迁微信云开发静态托管；`assetBase` 下发的切换口子已预留，端上零改动。

**整改机制备查**：核查不通过会连续两次电话 + 邮件/短信/站内信通知；延期最多 2 次、每次 ≤5 个工作日；逾期未整改 → 取消接入或管局注销。（v1.9 的「10–15 天整改期」无官方出处，不作依据。）

## 7. 境外托管的根本张力（R1，接受）

风险链：内容与请求由 Cloudflare 境外节点响应 ↔ ICP 备案实质要求「服务在境内」→ 批量整改 → 极端情况注销备案 → 合法域名失效。**不改架构的三个理由**：改造成本远高于风险（低概率、慢变量）；同类「境内备案 + 境外托管」组合普遍正常运营；微信侧备案校验已通过。**兜底**：端上冷启动失败回退 `wx.setStorage` 里上次成功的全量快照，展示「离线内容（最后更新于 X）」而非白屏——这是备案万一失效时的唯一出路。
